THE PROGRESS TAB

Main Progress Tab Screen: The Progress Tab will be a tab with 4 cards in a carousel. Each of these 4 cards will be a button that leads to a new screen. The Progress Tab main screen will have a gradient background that will consist of The Green, Blue, and Purple colors used for the exercise cards in the workout tab. Near the top middle of the Screen there will be a big hero heading that says "Your Athletic Journey" and then below in smaller, grayer text it will say "Every session, set, and rep - transformed into meaingful progress you can see"

Progress Graph Screen and Function: Ok Cursor, brace yourself, because this is going to be one of the most important parts of the app. Ok, so as you know we already have progress graphs, and you know how they work, but in case you work I’ll refresh you. Currently, when you search an exercise in the progress graph you are able to view metrics on that exercise based on what the exercise is. When I say that, I mean depending on what type of exercise square the exercise is most commonly logged in, that affects the metrics on the y axis of the graph. So take the exercise “push ups” for example, let’s say a user typically logged “push ups” in an “exercise” exercise square, which has boxes to type reps and weight, so then the given options for the progress graph would be reps, weight, and reps x weight, because that is what we coded, for specific exercise squares to have different y axis metrics. Also the current progress graphs are MODE dependent, so if I was in basketball mode and I searched for an exercise I ONLY logged in lifting mode, when I would not see the data for that exercise on my basketball mode progress graph. Ok, so now that I confirmed the logic for the OLD Progress Graph, I want to introduce to you our NEW Progress Graphs. 

These new progress graphs are going to have different VIEWS, you can think of them as modes but we’ll call them views to not get them confused with sport modes. The Progress Graphs views will have different Views depending on their sport mode. So a progress graph being looked at in basketball mode should have different views then a progress graph being looked at in lifting mode, and all of the other sport modes as well. Below I will list the different views for these graphs for EVERY sport mode and I will detail what the X and Y axis will be for each different view and how each view will work and be displayed.


Just to start and make this apparent, the X axis for ALL of these graphs will be the time intervals. BUT we are actually going with a different set of options for time intervals. The options are “30 Days”, “90 Days”, “180 Days”, and “360 Days”. “30 Days” will have 6 points on the x axis, one for every 5 days “90 Days” will have 6 points on the x-axis, one for every 15 days. “180 Days” will also have 6 points on the x-axis, one every 30 days. “360 Days” will have 6 points on the x-axis as well, one for every 60 days. 

ALSO, another important note is how I want the data to actually be displayed for again, ALL of the graphs. The HIGHEST data point on the graph and the LOWEST data point on the graph should be the highest and lowest points on the y axis, so no extra points above or below the highest or lowest points on the y axis. ALL of the graphs now have 6 points, so there should also be SIX y-axis points on every graph too, no need to add extra y-axis points on these new graphs, just the necessary 6 will be fine. BUT, I want these 6 points to actually be accurate and not just preset at the same heights from largest to smallest. What I mean is, if there are 2 points that are very close, then the 2 points should APPEAR very close on the graph, I don’t want you to make a preset orientation of the points exactly spaced apart from largest to smallest because the data will almost never actually be exactly spaced apart. So the data needs to be displayed accurately, like if there is one point thats value is way higher than the other points values then that high point should appear way higher than all of the other values.

Lifting Mode:

There will be 2 Views for Lifting Mode, the Performance View and the Tonnage View. The performance view will take the users HIGHEST single set reps x weight in a time interval point and the reps x weight number will be the Y axis, and the x axis will be the time intervals. So for example, if the user is viewing “Bench Press” on a 360 Day setting, then each of the 6 data points should show the highest single set reps x weight for exercises named “Bench Press” in each 60 day period. So the first point would show the highest single set reps x weight for exercises named bench press IN that first 60 day time period. So logically the code should find the HIGHEST single set reps x weight logged in that first 60 day time period, then also find the Highest single set reps x weight logged in that next 60 day time period and so on for every single data point. But if the graph setting was changed to the “30 Day” time period then logically the graph would have to find the highest single set reps x weight logged in every 5 day period. The 2nd VIEW for lifting mode will be the Tonnage view. This view has the same structure and principles are the performance view with one key difference, instead of the value of each point being determined by the highest single set reps x weight, the y-axis value of the points will be decided by the average reps x weight x sets for every square of the exercise. So let’s say the user logged “bench press” twice in a 5 day time interval, one day their total reps x weight x sets was 3000 and the other day their total reps x weight x sets was 5000, again this is PER EXERCISE SQUARE for that exercise, not per set, as sets are part of the equation. Well then clearly their average y-axis value for that 5 day time period is 4000. So if they viewed a graph set to the 30 day setting, then their latest point would be at 4000 since that was their average reps x weight x sets in the last 5 day time period for the exercise.

Basketball Mode:

There will be 5 Views for Basketball Mode. The first 2 views are going to be the Performance View and the Tonnage View, and these views can ONLY be displayed if the user searches an exercise that they primarily logged in “Exercise” type exercise squares. As you know in basketball mode workouts there are 3 types of exercise squares, “Exercise”, “Shooting” and “Drill”. Performance and Tonnage can ONLY be viewed if an exercise logged in an “Exercise” square is searched. This is why the Lifting Mode only has these 2 views, because the only exercise type square that lifting mode workouts have is “exercise.” The 3rd View for basketball mode is ONLY allowed to be displayed if the exercise searched is primarily logged in a “Shooting type exercise square. This 3rd view is the Shooting % View. In this view the y-axis values are calculated simply using the average shooting % from logged shooting exercise squares in the time interval. So if the user is viewing the graph on the 90 Day setting for example, one data point will display the average % from all of the logged shooting sets in the 15 day time interval. This one is pretty simple, as each shooting set should calculate the % of the set, so this view just needs to display the average of that % for every set in the time interval for each point. The 4th view is the Jumpshot View. This view, like the last view, is ONLY allowed to be displayed if the user searches an exercise that is primarily tracked in “shooting” type exercise squares. This view’s y-axis points are determined by the average number of logged attempted shots for the exercise in the given time interval. So for this one, instead of taking the set average, we want to take the SHOOTING SQUARE average for “attempted” shots in the given time interval. In every shooting square set the user tracks their attempted shots, so here we want to COMBINE all of the attempted shots logged in the given time interval and divide by the number of shooting squares logged with this exercise name, to get the average number of attempted shots per time this shooting square was logged. This average number of attempts per shooting square is the number to display on the y-axis for this view and of course dependent on the time interval. The 5th basketball mode view is the Drill View. This view can ONLY be displayed if the searched exercise was tracked in a “Drill” exercise square. The y-axis value for each point will simply be calculated by the total number of reps logged for that exercise. It’s pretty simple,  it’s just the total number of reps logged under that exercise for the given time interval. There is no average for this view, just a total.

Football Mode:

There will be 5 Views for Football Mode. 2 Views will be Performance and Tonnage. Remember, these 2 views can ONLY be displayed when the user is searching an exercise that they logged primarily in exercise type squares. Just to clarify, when I say only in “exercise” type squares, I mean only in exercise type squares in football mode, NOT all exercise type squares, that goes the same for every mode, you can only pull data to your progress graph from exercises tracked in THAT mode. The 3rd View will be the Completion View. This view can ONLY be displayed if the searched exercise is logged in “Drill” type exercise squares, but this view is NOT the same as the Drill View from basketball mode. Football Mode “Drill” exercise type squares track “Reps” and “Completed” (which means completed reps). If this is not in the logic already, I want this to calculate a PERCENTAGE, similar to how the “attempted” and “made” in the basketball mode “shooting” exercise type square calculate a percentage. The percentage should be completed / reps. So for this Completion View, the y-axis values for the points are calculated by the average completion percentage on each set of the drill being logged. So if the user logged 2 exercises called “routes” in “Drill” type exercise squares in a 5 day time period, and the completion percentages for all of the logged sets were for example, 50%, 50%, 70%, and 70%, then the average completion percentage for that 5 day time interval is 60%. So if the graph was on the 30 Day setting, then that point would have a y value axis at 60%. The 4th view for football mode progress graphs is the Speed View. So the “Sprints” exercise type square in football mode actually has inputs for Reps, Distance, and Average Speed. For this Speed View, it can ONLY be displayed if the searched exercise was logged in “Sprints” type exercise squares. The y-axis points for this view will be calculated by taking the highest single set distance divided by avg. time for a given time interval. The 5th view will be the Sprints View. This view’s y-axis value will just be calculated by the total number of reps logged for this exercise in the given time interval. Again, this view can ONLY be displayed if the searched exercise is most commonly logged under “Sprint” exercise type squares.

Baseball Mode:

There will be 5 Views for Baseball Mode. The first two are again the Performance View and the Tonnage View, which are calculated the same and can ONLY be displayed if the searched exercise is most commonly logged in “exercise” type squares. The 3rd View will be the Hits View. This view’s y-axis value will be calculated simply with the total number of reps logged under “Hitting” type squares for the given time interval. This view can ONLY be displayed if the searched exercise is logged in “Hitting” type squares. The 4th view is the Distance View. This view’s y-axis value is calculated with the average number of “avg. distance” per set. “Hitting” exercise squares track “av.g distance” so to calculate you could add all of the “avg. distance” and then divide by the total number of sets for this exercise to the average number of “avg. distance” in the given time interval. This view can ONLY be displayed if the searched exercise is most commonly logged in “Hitting” type squares. The 5th view for baseball mode is the Fielding View. This view can ONLY be displayed if the searched exercise is logged most commonly under “Fielding” type squares. To calculate the y-axis for this value it will be the total (reps x distance) / sets, in order to get the average total distance per set.

Soccer Mode:

There will be 5 Views for Soccer Mode. The first 2 views are again Performance View and Tonnage View, which again can only be displayed if the searched exercise is logged in “exercise” type squares. The 3rd view is actually going to be another repeat view, which is the Drill View. Soccer mode “Drill” type squares have the same inputs as the “Drill” type squares in basketball mode, so the Drill View will also be present in the soccer mode with the same logic as the basketball mode Drill View, similar to how the Performance and Tonnage views are present in every mode, because every mode has the same exercise squares, soccer mode has the same drill type square as basketball, so it gets the same view. So keeping the Drill View consistent, it can only be displayed if the searched exercise was logged primarily in the “Drill” type exercise. The 4th view for soccer mode is the Shots View. This view can ONLY be displayed if the searched exercise is logged in “Shooting” exercise squares in soccer mode of course. This view’s y-axis value points are calculated with the total number of reps logged in the given time interval. The 5th view is the Shot Distance View. This view can ONLY be displayed if the searched exercise is logged in “shooting” type exercise squares. This view’s y-axis values are calculated with the average distance per shooting set. So it can be calculated by adding the total distance from all sets from this exercise, divided by the number of sets, to get the average logged distance per set.

Hockey Mode:

Hockey Mode will have 5 Views. Skill Map Screen and Function: You can think of the skill map screen as sort of like an upgraded version of the Progress Graph. The user will be able to change the sport mode of the Skill Map Display and then change the View of the Skill Map display based on the available views depending on the sport mode. Then, depending on the view of the Skill Map the user will be able to compare exercises compared to the highest value exercise on their map. Again, the skill map is going to use the exact same VIEW logic that was explained and detailed in the Progress Graph Screen section of this documentation. 

So let’s say for example the user sets their Skill Map to Lifting Mode and from there the Tonnage View. Now the user can add up to 6 exercises to their map. A big difference from the Progress Graph to the Skill Map is that the View chosen actually restricts the exercise pool for the skill map, while for the progress graph the exercise searched dictated the view that could be chosen for the graph. So here the Tonnage View chosen means that the only exercises that can be selected for the skill map are exercises that the user logged under “exercise” type squares for lifting mode, since the graph is in lifting mode. So the skill map has the same logic, just the exercise options come after the view is chosen, while in the progress graph the view options came after the exercise was searched. A similarity of the 2 screens is that both work on time intervals, so just like the progress graph the skill map is going to work off of a chosen time setting. Only, instead of displaying the data in points like the progress graph, the Skill Map is just going to display data from the last # of Days chosen. So if the skill map setting is on “90 Days” then the data that the skill map pulls is all of the totals, averages, and highest single sets, ALL from workouts logged in the PAST 90 days. That is an important distinction. The progress graphs show the past # of days in time interval points, while the Skill Map just shows all of that data in one big point. 

Now I am going to explain the actual display and comparison part of the Skil Map. Let’s stick with our Tonnage View example.  Let’s say that the 6 exercises in the time interval’s tonnage values were these 6 values: 10000, 7000, 8000, 2000, 1500, and 4500. So the way the comparison is going to work, is the comparing metric of the exercises is going to work off of the HIGHEST value out of the chosen exercises in the map. The highest tonnage from these 6 values is 10000, so this exercise will receive a 100% on the skill map. The measuring metric for the skill map is the SAME for every exercise, and we can do this because the only exercises on the map should all be in the same view. This skill map metric will be out of 100%, and like I said the metric for each exercise works off of the highest value. Back to the example, let’s say Bench Press was the exercise with the tonnage of 7000 in the time interval. Since the highest exercise in the map was 10000, we’ll divide our bench press tonnage by the highest value to get our skill map metric for bench press. 7000/10000 is 70% so our skill map metric for bench press would be 70%. And that is how these exercises get compared, it is clear that the exercise with the 10000 tonnage was better in the time interval with the 7000 tonnage because it was 100% while bench press was only 70%. This does look simple now, because we are working with an easier View to compare, Tonnage, but this metric calculation system really helps when working with harder views.

Let’s look at another example View, like the Shot Distance View. This View is calculated by the average distance per set, and is restricted to only hockey and soccer specific “Shooting” type squares, and you should know this from the description and key in the progress graph screen documentation. Let’s say the user set the mode to soccer, and set Shot Distance as the View, and set the time setting to “360 Days”. Then the user can search through their exercise options for the exercises to add to the skill map that have to be logged in “shooting” type squares. Let’s say they choose 6 exercises and those 6 exercise’s average shot distance are as follows: 10, 13, 17.5, 20, 21, 18. Well 21ft of distance would be the 100% on the chart, and then the calculation for the rest of the exercises distances would be their number divided by 21 to find their percentage for their metric %. Just to give more clarity, a user might log exercises like “Right Wing Shots,” “Center Shots,” “One Touch Shots,” and then they could compare these exercises based on their shot distance to visually see which shots they shoot from more or less distance. We have to make visual progress in these VIEWS like “Shot Distance” and “Tonnage” or else there would be too many different things to compare at once, these Views all focus on a specific thing that we can then compare using the calculation for the skill map metric %.

Consistiency Score Screen: This screen will be accessed when a user clicks the third, puple card in the Progress Tab. This screen will display a score out of 100 with 100 little bars in semicircle pattern. This score's purpose is calculate how consistient the user is with their training. This semicricle 100 bar pattern will be at the top of this screen, displaying their score number in the middle of the bar pattern, and the score number should match the number of bars colored in. 80% of the consistiency score will be calculated based off how many workouts the user logs compared to how many they scheduled. So if the user schedules 10 workouts across their sport modes in a week, and they log 5, then 80% their consistiency score for the week will be 50 because 5/10 is 50%. But that is only 80% of the score. The other 20% of the score is calculated with streaks and gaps. If they have a 5 day workout gap then they get 0 of the other 20% of the score. If they have a 4 day gap without a workout then they only get 5 points. If they have a 3 day gap then they get 10. If they have a 2 day gap they get 15 points. If they only have 1 day gaps or 0 gaps then they get 20. So for example if a user schedules 10 workouts, and logs 5, then they get a 50, but that is only 80% of their score. So let's say their longest gap in that week without a workout was 1 day, then they get 20/20 points for the other 20% of the score. So their score would be 50 multplied by 0.8 to get 40 + 20, so their consistency score would be 60. Here's another example, if a user scheudles 7 workouts, and logs 7 workouts, and has no gaps, then they would get a 7/7 for their logged workouts, which is 100%, and they would get 20 points for their 0 gaps. So 100 multipled by 0.8 gets 80 then you add their 20 points, and 80 + 20 =  100 which is a perfect consistiency score for the week. That is how the score will be calculated. The consistiency score will update at the beginning of every week, so once the week ends, the consistency score should update to the previous weeks score, because it has the entire week of data. Essentially the consistiency score displays the most recent full week of workouts. The main part of the screen will have the actual chart and data from this week, and then below will be a stacked list of previous weeks and the score from those weeks. Below the score from each previous week will be number that us either green or red and it will show the %increase or %decrease that weeks score is from the previous week. Also somewhere in the screen I want to display an "Average Consistency Score" that is just shows the average consistency score for the user. This score will simply be calcuulated by the total number of all the users consistency scores added up divided by the number of weeks the user has had a score, which is every week. If the user schedules zero workouts and logs 0 workouts then their consisteccy score will be 0. Also if a user doesn't schedule any workouts but logs some workouts, then their score will be entirely based on the gaps in their week. So if they schedule 0 workouts but log 2, and have a 3 day gap, well a 3 day gap is usually 10 points, but we are going to multiply it by 5 since the 20 points is now the entire score, so their score would be a 50. Similarly, if a user didn't schedule any workouts, but logged a workout 7 days in a row, then their score would be 20 x 5, which is a 100.
